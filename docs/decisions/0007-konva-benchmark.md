# 0007 – מדידת ביצועים: Konva ישירות מול React-Konva

סטטוס: **בוצע** (2026-11-25). מאשר את הכיוון שאושר (Konva ישירות).

## מה נמדד

לוח עם **5,000 קווים** (כל קו 50 נקודות, בצורת perfect-freehand), בדפדפן Chromium אמיתי, חציון של 3 הרצות.
המדידה נעשתה בסביבה בלי כרטיס גרפי, ולכן המספרים המוחלטים איטיים ממחשב רגיל – ההשוואה ביניהם היא החשובה.

| פעולה                    | Konva ישירות | React-Konva |
| ------------------------ | ------------ | ----------- |
| פתיחת לוח עם 5,000 קווים | 43 מ"ש       | 104 מ"ש     |
| תזוזת לוח (פריים אחד)    | 19.3 מ"ש     | 19.4 מ"ש    |
| הוספת קו חדש             | 18.9 מ"ש     | 18.5 מ"ש    |
| עדכון הקו שנכתב כרגע     | 0.01 מ"ש     | 0.1 מ"ש     |

## מסקנות

1. **React-Konva אינו איטי** בשימוש נכון. ההבדל היחיד המורגש: פתיחת לוח גדול איטית פי 2.4 (עדיין עשירית שנייה).
2. **צוואר הבקבוק האמיתי הוא הציור עצמו**, לא React: ציור מחדש של 5,000 קווים לוקח כ-19 מ"ש, יותר מפריים אחד (16 מ"ש). זה נכון בשתי הגישות.
3. ניסוי פתרון: בזמן תזוזה/זום מציירים את הקווים הגמורים **כתמונה אחת** – פריים ירד מ-19 מ"ש ל-**0.03 מ"ש**.

## ההחלטה

- ממשיכים עם **Konva ישירות**, מסיבות מבנה ולא מהירות: מנוע הציור נשאר עצמאי מ-React (ניתן לבדיקה ולהחלפה), ונדרשת שליטה ישירה לטכניקות הביצועים:
  - צילום-מצב של הקווים בזמן תזוזה וזום, וציור חד מחדש בסיומם.
  - ציור קו חדש בלבד בסיום כתיבה (בלי לצייר מחדש את כל הלוח).
  - הקו שנכתב כרגע מצויר על משטח נפרד ומהיר (desynchronized) להפחתת השהיה.
- React ממשיך לנהל את הסרגלים והחלוניות.
